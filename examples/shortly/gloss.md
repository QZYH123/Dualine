# shortly 是怎么工作的

这份对照笔记带你看懂 shortly 是怎么运转的。不要只读左边，请跟着高亮看右边的真实代码。

## 这是什么

shortly 的工作是把一个长网址换成一个七位的短码。之后只要有人访问短网址，就会被带回原来的地方。对外，它只有[三个 HTTP 接口](src/server.ts#L18-L59)：一个用来把网址变短，一个用来跳转，还有一个用来查看被点了多少次。这就是整个服务。

## 缩短：第一道门

@[src/server.ts#L19-L30]当一个请求要缩短网址时，第一件事是检查它是不是真的网址。

清洗工作交给了专门的函数。它先拒绝[空值和非字符串](src/validate.ts#L14-L16)，再拒绝[过长的输入](src/validate.ts#L17-L19)。这些是最基本的防线。

如果看着像字符串，就交给[内置解析器](src/validate.ts#L21-L26)去理解。它必须是 `http` 或者 `https` 开头，[限制协议](src/validate.ts#L28-L30)可以挡掉 `javascript:` 这种危险链接。

作为公开服务，它还会拒绝指向[本机和内网地址](src/validate.ts#L31-L33)的请求，防止自己被人当成探测内网的跳板。最后，它会[抹掉片段](src/validate.ts#L35-L36)，免得同一个网址因为多了个 `#` 就在库里占两条。

## 缩短：造一个短码

@[src/server.ts#L65-L73]网址干净了，接下来需要给它配一个短码（代码里管它叫 `slug`）。

短码由六十二个[大小写字母和数字](src/slug.ts#L3-L4)组成，[固定七位长度](src/slug.ts#L6)。

为了让人猜不出规律，它用密码学模块生成[随机字节](src/slug.ts#L14-L15)。但这里有个数学陷阱：一个字节有 256 种变化，不能被 62 整除。如果直接除以 62 取余数，有些字母就会出现得更频繁。

所以代码[丢弃偏斜区间](src/slug.ts#L8-L10)，遇到 248 及以上的字节就直接扔掉，[只在公平区间取模](src/slug.ts#L16-L19)。这种方法叫拒绝采样，能保证每个字符出现的概率绝对相等。

## 缩短：落盘与重试

@[src/server.ts#L20-L26]短码生成后，要和网址一起存起来。

底层用的是 SQLite，结构极简，只有[唯一的表](src/store.ts#L19-L26)。短码本身就是主键，这自带了防重的功效——不用先去查库里有没有，直接[插入数据](src/store.ts#L46-L54)就好。

如果撞了主键，底层不会抛出异常，而是[通过错误码判断冲突](src/store.ts#L70-L76)并返回 `false`。

上层看到失败，[重试逻辑](src/server.ts#L66-L71)就会再生成一个新短码重试。连续五次撞车的概率极低，这个循环只是为了给「不可能」一个出口。

一切顺利的话，接口[返回成功](src/server.ts#L22-L26)。途中的任何问题都被捕获，[统一处理错误](src/server.ts#L27-L29)，由[错误处理器](src/server.ts#L75-L87)决定该骂客户端还是该记日志。

## 访问短码

有人点击了短链接，请求顺着[路由](src/server.ts#L46-L59)进来。

为了安全和速度，服务器先做[形式检查](src/server.ts#L47-L51)。只要看着不像[合法模式](src/slug.ts#L25-L29)，就直接回绝，根本不去碰数据库。

一旦格式没问题，就去[查库](src/server.ts#L52-L56)。底层的[读取语句](src/store.ts#L56-L58)会把原网址找出来。

找到之后，要做两件事。先是[记一次点击](src/server.ts#L57)，[执行更新](src/store.ts#L60-L62)增加计数。

最后是重头戏，把用户[跳转](src/server.ts#L58)到长网址。这里故意用了 302 而不是 301 状态码。301 是永久转移，浏览器会死死记住，下次自己直接过去；302 是临时转移，浏览器每次都要回来问一下，这样服务器才能数清楚到底被点了几次。

## 启动与退出

程序的生命从读取[配置](src/index.ts#L4-L6)开始。

它必须按[装配顺序](src/index.ts#L8-L9)做事：先准备好数据库，再把数据库交给服务器。这样服务器就不关心数据到底存在哪里，方便测试。

数据库在启动时[开启 WAL](src/store.ts#L32) 模式。这是一种日志策略，让读和写可以同时发生，对短链接这种「不停被读、偶尔才写」的场景非常完美。常用的 SQL 操作也会在启动时[预编译语句](src/store.ts#L35-L43)，以后每次用就很快。

服务器在监听前，[隐藏框架](src/server.ts#L15)标志位，也不忘把请求体[限制大小](src/server.ts#L16)，防止被巨大包撑爆内存。

当你想关掉它时（比如按下 Ctrl+C），它会执行[优雅退出](src/index.ts#L15-L23)：先拒绝新客，再关数据库，最后断电。

## 还没做的事

代码看完了，不妨看看它没做什么。比如，它没有做限流，[缩短接口](src/server.ts#L19-L30)谁都可以无限调用。要加上，可以在进这个路由前卡一个中间件。

它也没有过期机制。如果想让链接定时作废，要在[表结构](src/store.ts#L20-L25)里加一列，并在跳转前检查。

它还不支持自定义短码。其实要支持很简单，只需让请求带上想要的词，先过[检查自定义短码](src/slug.ts#L27-L29)，再走插入逻辑。万一[主键冲突](src/store.ts#L70-L76)，直接跟用户说「这个词被人用啦」就行。
